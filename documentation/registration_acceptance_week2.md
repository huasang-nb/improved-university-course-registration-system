# 第二周选退课跨模块验收

负责人 Zhang Yuhua。开发日期为 2026 年 11 月 15 日，开发基线为个人仓库 main 的 b9b52df。

## 本轮交付

新增独立验收程序 `automated_tests/registration_cross_module_acceptance.cpp` 和运行入口 `run_registration_acceptance.ps1`。程序直接调用现有选退课、学生查询、教师查询和管理员容量接口，补充组合失败条件与失败后数据保持的验证。

本轮复用已有 SystemContext 和业务接口。现有业务实现及共享接口保持原样。用户身份由测试显式构造，固定时间、6 学分上限和容量均为测试数据。

## 如何运行

在项目根目录使用 PowerShell 执行：

```powershell
.\run_registration_acceptance.ps1
```

需要支持 C++17 的 g++，可按现有脚本约定通过环境变量 CXX 指定编译器。脚本先编译、运行原有三套测试，通过后再编译、运行新增跨模块验收。任一步失败会返回非零退出码。

新增程序使用显式检查，即使编译时定义 NDEBUG 也会执行所有验收项。输出每个场景的 PASS 或 FAIL，遇到失败会报告场景及原因，最后统计检查数和失败场景数。

## 场景与业务依据

| 场景 | 验收内容 |
| --- | --- |
| 退课后名额转移与重新选课 | A 退课后 B 占位，A 重选被拒时 Dropped 保留；B 退课后 A 可恢复原记录，重复请求不新增记录 |
| 同课程重复与满员同时成立 | 按原检查顺序先返回 AlreadyEnrolled |
| 时间冲突 学分超限 满员同时成立 | 先返回 TimeConflict，并检查所有学生原选课记录保持原样 |
| 学分超限与满员同时成立 | 先返回 CreditLimitExceeded |
| 开始时刻边界 | 开始前一分钟拒绝，恰好开始时可选，调用方无需先刷新 |
| 结束时刻边界 | 恰好结束时选课和退课都拒绝，已有 Active 及其他学生选课保留 |
| 相邻上课时段与学分边界 | 前一节结束恰好等于后一节开始时可选，总学分恰好达到上限可选 |
| 无效请求与其他学生隔离 | 不存在的教学班、退自己未选的班均拒绝，其他学生选课不被改动 |
| 容量缩小被拒绝 | 新容量低于有效人数时保留原容量和所有选课记录 |

每次跨模块核对从场景指定的学生与教学班集合出发，检查全部班级的余量、教师人数与名单、全部学生课表，以及数据一致性。失败场景额外比较完整选退课记录，覆盖误激活 Dropped、误插入、误删除或误改状态等情况。

## 本轮验证结果

在 b9b52df 独立副本中，原有三套测试通过，其中教师管理员为 326 项检查、0 失败；新增 9 个场景为 574 项检查、0 个失败场景。相同新增程序在 Zhu 的 f6cd49a 独立副本中也通过 574 项检查，验证两版接口的兼容性。

开发时还使用额外临时副本，故意注入“满员失败路径误激活 Dropped 记录”的错误，新增程序能发现记录改变并返回失败。

本轮完成内存业务联调。真实存储保存失败、退出后恢复、真实登录与多人同时请求仍需在对应实现接入后验证，不能用本程序的通过结果代替这些测试。
